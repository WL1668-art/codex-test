# Production workflow

## Natural chapters and synthesis

Use transcript evidence plus the source’s own rhetorical structure. A chapter boundary should be explainable: a new question, theme, method, demonstration, example, conclusion, or explicit transition begins. Keep the number and length of chapters responsive to the source; do not make equal time slices.

For every chapter, capture:

- title, start, end, and boundary reason;
- core question and ideas;
- steps or method, pitfalls, conclusion, and concrete action items;
- keywords, valuable source timestamps, and suggested visual anchors.

Then build a cross-chapter synthesis: one-sentence overview, central problem, prioritized takeaways, workflow, common mistakes, action list, and return-to-source timestamps. Preserve the distinction between source claims and independently verified facts.

## Semantic keyframes

Inspect candidate frames against chapter evidence before retaining them. A frame earns its place when it materially clarifies a task, UI operation, parameter, diagram, transformation, evidence, or result. Prefer precise timestamps over uniform sampling. When two frames explain the same thing, retain the clearer or more complete one.

Record final frames as `file`, `timestamp`, `chapter`, `reason`, and `helps_understand`. The page must make the image-to-chapter relationship explicit.

## Page design

Use a single responsive HTML file with relative media paths and no front-end dependency. Include an editorial title plus the exact source title, source metadata, cover linked to the source, overview, takeaways, workflow, chapter navigation, full chapter cards, semantic frames, keywords, final summary, and working timestamp links.

Use page content to drive structure. Favor scannable cards, short lists, meaningful headings, and relationship/flow visuals only where they explain real source content. Do not add animation by default.
