# 生产工作流

## 阶段 1：命题与口径

确认人物、时间跨度、受众、事实/虚构边界、期望节点密度与章节数量。复述 OHLCV 的叙事含义，并声明 0–100 仅为叙事指数。

此阶段不可写人物页面。

## 阶段 2：人物研究

建立候选事件池，优先选择真正改变人生斜率、风险、影响力或制度位置的节点。核对年份、事件因果和争议措辞；对存疑年份使用谨慎表达。虚构人物则以原作或用户设定为准，并区分正史、改编与推演。

## 阶段 3：数据成表

1. 先确定 chapters，再把候选事件分配到章节。
2. 为每个事件写 title、phase、note，再评估 OHLCV，避免先画理想曲线后硬套史实。
3. 保持年份非递减；同年多件大事可拆分。
4. 调整相邻 `close -> open` 连续性，但不能以连续性为由扭曲事件意义。
5. 运行 validator，人工复查走势是否与 note 一致。
6. 向用户交付纯数据并取得锁定确认。

数据未锁定前，禁止进入页面实现。

## 阶段 4：页面实现

默认以单文件 HTML + CSS + Canvas + 原生 JavaScript 实现。可以复制 `assets/golden-template.html` 作为技术基线，但必须：

- 替换全部人物数据、标题、副标题、章节和叙事；
- 保留数据与绘制、播放、镜头、时间轴、叙事卡的职责分离；
- Canvas 颜色从 CSS Variables 读取，四主题共用一套 DOM 和状态机；
- 未来节点保持未揭示，轨迹连续领跑，K 线和 volume 分层追随；
- 手动节点跳转及时响应，不强制重播整段追逐动画。

## 阶段 5：节奏与镜头

默认冻结：

| 参数 | 默认值 |
| --- | --- |
| 轨迹累计运动 | 约 4000ms |
| K 线延迟 | 220ms |
| volume 追加延迟 | 140ms |
| travel zoom | 1.00 |
| focus zoom | 1.12 |
| chapterReview zoom | 0.82 |
| globalReview zoom | 0.50 |

状态顺序为 `opening -> travel/focus -> chapterReview -> ... -> globalReview`。opening 与每次 chapterReview 都是用户闸门；等待期间轨迹、揭示和镜头冻结。focus 沿用实现层的重点节点判定，不向 candles 临时增加私有字段。

只有用户明确要求时才调整冻结参数。调整后必须重新验证节奏、暂停恢复、章节衔接和全局收束。

## 阶段 6：主题与跨端

- 四主题：暮山紫、宫墙朱、山水墨、暗夜盘。
- 主题只切换 CSS Variables 和 Canvas 调色，不改变当前节点、揭示进度、镜头或计时。
- 手机端用点击完成全部流程；桌面可额外保留空格快捷键。
- 时间轴和章节导航在窄屏内部横向滚动，不带动整页。
- globalReview 的窄屏年份按宽度抽稀，保留首、末、当前和重要章节边界；只隐藏文字，不删除 K 线、轨迹或 volume。
- 为首末 K 线、当前标签和高亮保留安全边距。
- reduced-motion 可缩短过渡或加快插值，但不得自动越过 opening 或 chapterReview。

## 阶段 7：验收与 Git

按 `acceptance-checklist.md` 做真实浏览器验收，并运行 validator。至少对一个失败假设做对抗检查，例如：暂停后动画仍偷跑、主题切换重置进度、窄屏末端被裁切、reduced-motion 跳门。

只有数据、交互、跨端和控制台都通过后，才可在用户授权下提交。提交时只暂存目标产物，不夹带截图、缓存、测试 profile 或无关目录。发布、push、PR 和 merge 分别遵循仓库规则及用户授权。
